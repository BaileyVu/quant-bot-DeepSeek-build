4.4 Commands to Demonstrate
After installation (pip install -e .[dev]):

Show config: quantos config

Start application: quantos start (logs startup).

Fetch historical data:

bash
quantos fetch --symbol BTCUSDT --days 1
This fetches the last 24 hours of 1-minute candles, validates, stores in data/parquet/BTCUSDT.parquet.

Query data via DuckDB:

bash
quantos query --symbol BTCUSDT --start 2025-01-01T00:00:00 --end 2025-01-02T00:00:00
Shows the first 10 candles.

Live feed:

bash
quantos live --symbol BTCUSDT
Connects to Binance WebSocket and prints completed 1-minute candles. Press Ctrl+C to stop.

All commands work as intended and demonstrate the Milestone 1 capabilities.

4.5 Limitations and Blockers
Pagination: The fetcher uses a simple loop with limit=1000; it may miss data if the requested range has more than 1000 candles due to potential gaps? Our loop handles it by incrementing start_time; but we must be careful with Binance's rate limits. For MVP, it's acceptable.

Live WebSocket: We implemented a basic WebSocket client using websocket-client. It runs in a background thread; the callback prints candles. It is not yet integrated with storage (that will be in later milestones). The WebSocket library may need to be installed (websocket-client).

DuckDB registration: We register all Parquet files as a view. If multiple symbols exist, they are unioned; queries filter by symbol. This works but we should ensure Parquet schemas match across symbols.

Tests: Integration tests are not run by default; we rely on mocking for CI.

Error handling: Limited retries and backoff; can be improved but not required for MVP.

4.6 Recommendation for Milestone 2
With Milestone 1 complete, we now have a reliable market data layer that can fetch historical and live data, validate it, and store/query it. For Milestone 2, we should focus on Feature Engineering (as per docs/004). The next step is to build the Feature Engine that transforms raw candles into a set of features (10–15 features) for the model. This will include:

Define a FeatureSet specification (features list).

Implement feature computation (e.g., returns, volatility, volume ratios, technical indicators like RSI, MACD, etc.) using Pandas/NumPy.

Store computed features alongside candles or in a separate Parquet file.

Provide a CLI command to compute features for a given date range.

We should keep feature engineering simple and deterministic, using only the candle data. We must avoid overcomplicating; start with a minimal set (e.g., price changes, high/low ratios, volume momentum). Ensure that the feature computation is testable and that the pipeline can be integrated later with the Alpha Engine.
